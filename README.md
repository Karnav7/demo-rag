# dummy-rag

A Graph-RAG investigation demo for financial crime. You ask questions about a fictional world of companies, people,
accounts, transactions and sanctions entries ("Who ultimately owns Meridian Trade LLC?", "Why was this wire
flagged?"). Each answer cites its claims and shows the evidence it was built from: the subgraph, the extracted
facts, the source passages, the Cypher that ran, and a timed trace of the retrieval pipeline.

The whole pipeline (lexical, vector, hybrid fusion with RRF, graph expansion, ranking, grounded answer) runs in
the browser over a bundled snapshot of the graph. Apart from the Inter web font, nothing is fetched at runtime and
nothing leaves the page.

> **Fictional data for demonstration. Not financial or legal advice.**
> Every person, company, account, address, registration number, case and document in this app is invented.
> Any resemblance to real entities is coincidental. Regulation excerpts are paraphrased for illustration.

## Running it

Requires Node 20.19+ or 22.12+.

```sh
npm install
npm run dev        # dev server at http://localhost:5173
npm test           # unit and component tests (Vitest)
npm run build      # type-check, then a production build in dist/
npm run preview    # serve dist/ locally
```

End-to-end tests use Playwright against a production build:

```sh
npx playwright install chromium   # once
npm run e2e                       # builds, serves on :4173, runs e2e/
```

To capture full-page screenshots of the chat in both themes at desktop and phone sizes, set `SHOTS_DIR`:

```sh
SHOTS_DIR=/tmp/shots npm run e2e -- screenshots
```

## The backend seam: `VITE_CHAT_URL`

The UI talks to a `ChatClient` that streams `stage`, `token` and `done` events, mirroring a single `POST /chat`
endpoint. The Architecture page in the app documents the request and event types.

The composer offers two data sources:

- **Offline snapshot** runs the in-browser engine over the bundled graph.
- **Live Neo4j** is **simulated** until a backend URL is configured. It is labelled and remembered like a real
  connection, but answers still come from the snapshot.

`VITE_CHAT_URL` is read at build time and is the place to point Live at a real service. The HTTP client for it is
not written yet: with the variable set, choosing Live reports an error instead of answering. Leave it unset for
the demo.

## Deploying

`.github/workflows/pages.yml` builds with `npm ci && npm run build` and publishes `dist/` to GitHub Pages on every
push to `main` (or by hand from the Actions tab). Enable Pages for the repository with "GitHub Actions" as the
source. The app uses relative asset paths and hash routing, so it works under any sub-path.

## Project layout

```
src/data      the fictional world (world.json, generated by scripts/gen-world.ts) and its loader
src/engine    retrieval pipeline: intents, lexical, vector, fuse, expand, rank, answer, cypher
src/client    the ChatClient seam and the in-browser snapshot client
src/store     conversations, settings and selection, persisted to localStorage (dummy-rag.*)
src/ui        shell, chat, evidence panel, graph views, Guide and Architecture pages
e2e           Playwright smoke tests
docs          design spec, plan and the Lattice parity report (docs/parity.md)
```
